## 1. 机器与 EC 基础

目标机器：

- 荣耀 MagicBook 14 Pro 2025
- 32GB + 1TB
- Windows 11 x64
- 荣耀电脑管家已安装

EC（Embedded Controller）通过标准 ACPI 端口访问：

```
EC_SC   = 0x66   状态/命令
EC_DATA = 0x62   数据
```

读 EC RAM：

```
等待 IBF=0
向 0x66 写 0x80
等待 IBF=0
向 0x62 写地址
等待 OBF=1
从 0x62 读数据
```

写 EC RAM：

```
等待 IBF=0
向 0x66 写 0x81
等待 IBF=0
向 0x62 写地址
等待 IBF=0
向 0x62 写数据
```

原项目 C-sharpEC 在 J8 系列上写的是 `0x92/0x93`；
本机实测阈值在 `0x80/0x81`。

## 2. 本机寄存器地图（实测）

| 地址 | 含义 | 实测值 |
|---|---|---|
| `0x80` | 恢复充电下限（百分比） | 100% 时 `0x00`；家用 40；办公 70 |
| `0x81` | 停止充电上限（百分比） | 100% 时 `0x64`；家用 70；办公 90 |
| `0x85` | 模式索引（低） | 家用 `0x01`、办公 `0x02`、差旅预计 `0x03`、关闭 `0x00` |
| `0x87` | 模式索引（高/重复） | 与 `0x85` 相同 |
| `0x89` | 充电允许状态 | `1`=允许充电，`0`=禁止充电 |
| `0x50` | 状态镜像 | 开启 `0x13`，关闭 `0x07`；可写但改了不起作用 |
| `0x76` | 电源/充电状态 | 插电 `0x80`，拔电 `0xC0`；不是控制位 |
| `0x7B~0x7F` | 其他数据 | 曾是 `50 46 ...`，与阈值无关，属于干扰项 |

模式与阈值对应：

| 模式 | 0x80 | 0x81 | 0x85/0x87 |
|---|---|---|---|
| 家用 70/40 | `0x28`（40） | `0x46`（70） | `0x01` |
| 办公 90/70 | `0x46`（70） | `0x5A`（90） | `0x02` |
| 差旅 100/95（预计） | `0x5F`（95） | `0x64`（100） | `0x03` |
| 关闭 | `0x64`（100） | `0x00` | `0x00` |

`0x89` 的行为：

- 家用模式，电量 88%：88 > 70 → `0x89=0`，禁止充电；
- 办公模式，电量 88%：88 < 90 → `0x89=1`，允许充电；
- 关闭模式：`0x89=1`，允许充电。

所以 `0x89` 不是“总开关”，而是**当前是否允许充电**的状态。

## 3. 荣耀官方控制链路

### 3.1 阈值：HardwareHal.dll + BIOS WMI

`HardwareHal.dll` 导出：

```
HalInit
HalQueryInformation
HalSetInformation
```

反汇编得到 category 8（电池）的调用方式：

```c
HalInit(8, 0);

// 读阈值（BIOS WMI 0x1103）
HalQueryInformation(8, 0, 12, out[2], 2, &status, 0);

// 写阈值（BIOS WMI 0x1003）
HalSetInformation(8, 0, 12, in[2], 2, &status, 0);
```

`SetCat8` 内部把两个字节打包成：

```
03 10 A B   // 命令 0x1003，A/B 为两个阈值字节
```

`GetCat8` 发送：

```
03 11       // 命令 0x1103
```

并从响应第 1、2 字节取回两个阈值。

字节顺序并不直观：不同 BIOS 可能返回 `[下限, 上限]` 或 `[上限, 下限]`。
程序的处理是：

1. 先读当前两个字节；
2. 如果第一个更小，认为顺序是 `[下限, 上限]`；
3. 先按这个顺序写，回读校验；
4. 不匹配再换另一个顺序。

最终写入的仍然是 EC `0x80/0x81`，所以**最终版本确实会写 EC 值**，
只是走官方 HAL，而不是直接端口 I/O。

### 3.2 模式：注册表 + MBAMainService

注册表：

```
HKLM\SOFTWARE\PCManager\MBAPowerManager
    PowerSafeManagerStatus = "1" / "0"
    PowerSafeManagerMode   = "0" / "1" / "2"
```

**这两个值必须是 REG_SZ 字符串**，不是 DWORD。

| `PowerSafeManagerMode` | 模式 |
|---|---|
| `"0"` | 家用 70/40 |
| `"1"` | 办公 90/70 |
| `"2"` | 差旅 100/95 |

`MBAMainService` 读取这两个值后，设置 EC：

```
0x85/0x87 = 模式索引
0x89      = 当前是否允许充电
```

只写注册表不够：服务需要重启（或收到 UI 的 IPC）才会重新读配置。
本程序通过 `ServiceController` 停止/启动 `MBAMainService`。

## 4. 开发过程

### v1.0：照搬原项目 + 改寄存器

- 把原项目的 `0x92/0x93` 改成 `0x80/0x81`；
- 通过 `HardwareHal` 写阈值；
- 程序能显示“停止 80% / 恢复 70%”，但充电不停。

原因：只写了阈值，没有设置 `0x85/0x87/0x89` 模式标志；
EC 不认为“电池安全管理”已启用。

### v1.1：加直接 EC 端口写入

- 引入 WinRing0/RwDrv，直接写 `0x66/0x62`；
- 有时能写进去，但和荣耀 EC 驱动/服务并发访问；
- EC 事务互相打断，读回随机值；
- 最终把 `0x80/0x81` 写成了 `23/192` 之类的非法值。

结论：**直接端口 I/O 在这台机器上不可用**。荣耀驱动/服务一直在访问 EC，
没有跨进程锁，两个进程的 `0x66/0x62` 序列会交错。

恢复方式：重启电脑，或打开荣耀电脑管家重新设置一次 100%。

### v1.2：回到 HAL + 重启

- 去掉直接 EC 写入；
- 只通过 HAL 写阈值，然后重启；
- 重启后 EC 确实变成 90/88，但充电仍不停。

原因：`0x85/0x87=0`，模式标志仍是关闭。
阈值存在，但 EC 不执行。

### v1.3：走官方模式（注册表 + 服务）

- 发现 `HKLM\SOFTWARE\PCManager\MBAPowerManager`；
- 写 REG_SZ 的 `PowerSafeManagerStatus` / `PowerSafeManagerMode`；
- 重启 `MBAMainService`；
- 官方模式生效：
  - 家用 70/40：88% 时 `0x89=0`，禁止充电；
  - 办公 90/70：88% 时 `0x89=1`，允许充到 90%；
- 但 UI 把模式文字和刷新按钮挤在一起，且不能自定义阈值。

### v1.4：尝试“自定义阈值 + 模式联动”

- 用户设 80/70，自动选择办公 90/70 作为载体；
- 先写 `0x80/0x81=80/70`，再写注册表 mode=1，重启服务；
- 结果：`0x80=0x46`、`0x81=0x50`，但 `0x85=0x00`、`0x87=0x00`；
- 服务拒绝了这个组合，模式没有启用。

结论：**服务只接受精确匹配的模式阈值**。
80/70 不对应任何官方模式，所以 `0x85/0x87` 保持 0。

### v1.5：动态模式切换（实验）

为了模拟 80/70，尝试：

- 平时用办公 90/70（允许充电）；
- 电量 ≥80% 切家用 70/40（禁止充电）；
- 电量 ≤70% 切回办公 90/70（恢复充电）。

原理可行，但：

- 需要程序后台常驻；
- 每次切换都要重启 `MBAMainService`，2～5 秒；
- 模式标志会来回变化；
- 只支持 70%～90% 的上限，范围有限。

最终没有作为默认版本。

### v1.6：最终版

- 只保留三种官方模式；
- UI 同时显示注册表值和 EC `0x80/0x81`；
- 刷新按钮独立右上角，不遮挡文字；
- 增加“电脑管家退出后自动重新应用模式”。

## 5. 踩坑记录

### 5.1 直接写 EC 端口会和荣耀驱动抢总线

这是最大的坑。表现：

- 读回值随机跳变；
- `0x81` 出现 `0x17`、`0xC0`、`0x17` 等非法值；
- 有时写入成功，有时完全没反应；
- 最终 EC 进入奇怪状态，需要重启/电脑管家恢复。

原因：荣耀 `HNOs2Ec` 驱动/服务也在读写 `0x66/0x62`，没有跨进程互斥。
EC 的“命令-地址-数据”三步事务一旦被另一个进程插入，就会错位。

**不要在这类机器上直接端口写 EC。**

### 5.2 只写 0x80/0x81 不够

`0x80/0x81` 只是阈值。EC 还需要：

```
0x85/0x87 = 模式索引（1/2/3）
0x89      = 当前允许/禁止充电
```

没有模式标志，阈值不会执行。

### 5.3 0x76 不是控制位

曾以为 `0x76` 的 bit6 是充电禁止位，因为：

- 插电 `0x76=0x80`；
- 拔电 `0x76=0xC0`；
- 电脑管家工作时 `0x76=0xC0`。

实测手动写 `0x76=0xC0` 会被 EC 立刻改回 `0x80`，充电也不受影响。
它是电源/充电状态，不是控制寄存器。

### 5.4 0x50 是镜像，不是开关

- 开启电池安全管理：`0x50=0x13`；
- 关闭：`0x50=0x07`；
- `0x50` 可写，但改了不起作用。

它只是模式状态的镜像/显示值，不要用它控制充电。

### 5.5 0x89 不是“总开关”

`0x89=1` 时也可能正在充电（电量低于模式上限）；
`0x89=0` 时表示当前禁止充电（电量高于模式上限）。
它是结果状态，不是用户开关。

### 5.6 注册表值必须是 REG_SZ

`PowerSafeManagerStatus` 和 `PowerSafeManagerMode` 是字符串：

```
"1" / "0"
"0" / "1" / "2"
```

写成 DWORD 时，电脑管家 UI 可能能读，但服务行为不稳定/不生效。
本程序用 `RegistryValueKind.String` 写入。

### 5.7 只改注册表不够，必须让服务重新读

改注册表后，电脑管家 UI 可能立刻显示新模式，但 EC 没变。
需要重启 `MBAMainService`（或由 UI 发 IPC）让服务重新设置 EC。

### 5.8 服务只接受精确的模式阈值

这是不能自定义 80/70 的根本原因。实测：

| 设置 | 0x80 | 0x81 | 0x85/0x87 | 结果 |
|---|---|---|---|---|
| 80/70 | `0x46` | `0x50` | `0x00` | 模式未启用 |
| 90/70 | `0x46` | `0x5A` | `0x02` | 办公模式 |
| 70/40 | `0x28` | `0x46` | `0x01` | 家用模式 |

服务会把写入的阈值和模式表比对；不匹配就不设置 `0x85/0x87`。

### 5.9 电脑管家退出会重置 EC 模式

电脑管家退出时：

- 把 EC 的 `0x85/0x87/0x89` 改回关闭状态；
- 但不改注册表。

结果：注册表仍是 `Status=1`、`Mode=0/1/2`，EC 却退出了电池安全管理。

v1.6 的做法：监控 `PCManager`/`PCManagerTray`/`HnFrontNavigator` 进程，
检测到退出后自动重新写阈值、写注册表、重启服务。

### 5.10 其他小坑

- `HardwareHal.dll` 需要从 `C:\Program Files\HONOR\PCManager` 加载，
  依赖同目录 DLL；用 `LoadLibraryEx` + `LOAD_WITH_ALTERED_SEARCH_PATH`。
- 注册表要读 64 位视图（程序是 x64）。
- 需要管理员权限：写 HKLM、重启服务、调用 BIOS WMI。
- 服务重启有 2～5 秒延迟，期间 UI 会卡一下。
- 早期版本引入 WinRing0，容易被杀软拦；最终版已移除。
- 直写 EC 把值写坏后，重启/电脑管家设置 100% 可以恢复；不要继续硬写。

## 6. 为什么最终不支持自定义上下限

官方服务只认三组精确值：

```
70/40、90/70、100/95
```

自定义 80/70 时：

```
0x80=0x46（70）
0x81=0x50（80）
0x85=0x00
0x87=0x00
0x89=0x01
```

模式没有启用，所以不会按 80% 停。

理论上可以用 v1.5 的“动态模式切换”模拟 70%～90% 的任意上限：

- 到 80% 切家用 70/40（禁止充电）；
- 到 70% 切办公 90/70（恢复充电）。

但它需要后台常驻、每次切换重启服务、模式频繁变化，
稳定性和体验都不如官方三模式，因此最终 v1.6 只保留三模式。

如果以后要做自定义，建议：

1. 保留 v1.5 的动态切换作为可选“高级模式”；
2. 明确限制上限范围 70%～90%、下限 40%～89%；
3. 加托盘/后台运行和异常恢复；
4. 不要回到直接端口写 EC。

## 7. 最终架构

```
Program.cs
  ├─ 管理员权限检查 / UAC 提升
  ├─ 命令行 --read / --mode / --restore
  └─ MainForm

MainForm.cs
  ├─ 三种模式单选
  ├─ 注册表值显示（REG_SZ）
  ├─ EC 0x80/0x81 显示（HAL 读取）

  └─ 电脑管家退出检测 → 自动重新应用

PowerManagerConfig.cs
  ├─ HKLM\SOFTWARE\PCManager\MBAPowerManager
  ├─ REG_SZ 写入
  └─ ServiceController 重启 MBAMainService

HalChargeController.cs
  ├─ LoadLibraryEx HardwareHal.dll
  ├─ HalInit(8,0)
  ├─ HalQueryInformation(8,0,12,...)
  ├─ HalSetInformation(8,0,12,...)
  └─ 字节顺序自适应 + 回读校验

BatteryInfo.cs
  └─ GetSystemPowerStatus
```

## 8. 移植到其他荣耀笔记本

最终版本**会写 EC 值**，所以不是“通用”的。移植时至少确认：

1. EC 阈值寄存器是否还是 `0x80/0x81`；
2. 模式标志是否还是 `0x85/0x87/0x89`；
3. 模式表是否还是 70/40、90/70、100/95；
4. 注册表键是否还是
   `HKLM\SOFTWARE\PCManager\MBAPowerManager`，值是否 REG_SZ；
5. `HardwareHal.dll` 是否导出 `HalInit/HalQueryInformation/HalSetInformation`；
6. 服务名是否还是 `MBAMainService`。

建议用 RWEverything 先做只读验证：

```
设置电脑管家模式 → 观察 0x80/0x81/0x85/0x87/0x89 → 记录对应表
```

确认后再改代码中的常量。可以把寄存器地址、模式表、注册表键抽成
`ModelProfile`，为不同机型做配置，而不是硬编码。
